# SQLD Practice 프론트

정리일: 2026-11-13. Next.js App Router·React·TypeScript·Tailwind CSS·TanStack Query를 사용한다.

## 화면

| 경로 | 기능 |
|---|---|
| `/` | 학습 범위·시험 시작·이어풀기 |
| `/study/{id}` | 즉시/일괄 채점·해설·재풀이·종료 |
| `/study/{id}/result` | 학습 결과·복습 |
| `/mock/{id}` | 선택·남은 시간·제출/포기 |
| `/mock/{id}/result` | 점수·합격/과락·해설 복습 |
| `/records` | 통계·오답 다시 풀기·시험 이력 |

현재167문항은 모두 검수 대기다. 학습·오답의 `검수 대기 문항 포함`, 시험의 `미검수 문항도 출제`를 선택한다. 기존8문항 학습은 그대로 남으므로 전체 범위는 새 학습으로 시작한다.

## 로딩·채점·저장

일반 학습은 문항·정답·해설·그림을 처음에 함께 받는다. 전체 데이터에서 현재 문제를 꺼내며 문항 이동 때 개별 문제/그림을 다시 요청하지 않는다. 캐시를 유지하고 탭 복귀/재연결 자동 재조회는 하지 않는다. 다른 기기 변경은 새로고침으로 반영한다.

선택·개별/일괄 채점·재풀이를 즉시 반영한다. 기록은1초 뒤 모아서 저장하며 미전송 상태를 localStorage에도 남긴다. 오류는 `기록 다시 저장`으로 처리한다. 저장 대기/실패가 로컬 채점·이동을 막지는 않는다.

학습 종료는 선택한 답안을 일괄 채점하고 기록 전송 후 확정한다. 미응답은 채점하지 않는다. 시험은50문항·90분이며 제출/만료 후 전체를 채점하고 미응답은 오답이다. 창을 닫아도 마감은 연장되지 않는다.

## 설치·환경

`frontend/`에서 실행한다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

http://localhost:3000 에서 사용한다. [백엔드](../backend/README.md)도 실행해야 실제 API와 연동된다. pnpm 실행기가 잘못 연결됐다면 `npx --yes pnpm@10.32.1 <명령>`을 사용한다.

프로덕션 명령은 `pnpm build`, `pnpm start`다. Geist 최초 빌드 다운로드에는 네트워크가 필요할 수 있다.

`.env.example`을 참고한다. 서버 전용 `BACKEND_API_URL`의 로컬 기본값은 http://127.0.0.1:8000 이고 브라우저는 동일 출처 `/api/v1`만 호출한다. 백엔드 `APP_ORIGIN`은 브라우저 주소와 맞춘다. 실제 환경변수·교재·그림은 Git이나 `public/`에 넣지 않는다. 앱 로그인은 없고 운영 접근은 Vercel에서 보호한다.

## 개발 도구와 확인 상태

명시적으로 필요한 경우 `pnpm lint`, `pnpm typecheck`, `pnpm test`를 사용할 수 있으나 현재는 사용자 지시로 실행하지 않는다. 최신 배포 빌드만 통과했다.

Playwright는 전용 개발 서버 `127.0.0.1:3210`과 직접 만든 HTTP 예제를 사용한다. 결과·trace는 Git 제외 폴더에 남긴다. 일부 테스트에는 예전의 클릭별 저장·서버 채점·포커스 재조회 기준이 남아 있어 현재 동작에 맞춘 정리가 필요하다. [과거5단계 결과](../2026-11-11-phase5-learning-ui-report.md)는 당시 코드의 기록이다.
